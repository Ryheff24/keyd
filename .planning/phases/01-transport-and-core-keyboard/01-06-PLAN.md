<objective>
Formalize the transport state machines on both macOS and iOS by replacing implicit state (boolean flags, optional-as-state, continuation existence) with explicit FSMs where every legal state and transition is defined in one place.

Purpose: The current transport code has 5 parallel connection pools and a 19-case switch on macOS, plus boolean shadow state on iOS. Every debug session traces to unexpected state combinations that the enum alone does not prevent. A pure transition function makes illegal states unrepresentable and every transition testable in isolation (which 01-07 will exercise).

Output: Pure `transition(from:on:) -> (State, [SideEffect])` functions for macOS and iOS transport, structured event log in SharedProtocol, TransportManager refactored to be a side-effect executor rather than a state machine itself.
</objective>

`AgentTransportState` enum — must capture ALL state currently spread across booleans and optionals:
```swift
enum AgentTransportState: Equatable, CustomStringConvertible {
    case disconnected
    case pendingUSBIdentity(deviceID: String?)       // USB connection awaiting identity verification
    case usbConnected(deviceID: String)               // Active USB session
    case pendingAWDLPool(slotCount: Int)               // One or more AWDL connections awaiting identity
    case pairingAWDL                                   // Unpaired: single AWDL pairing channel open
    case awdlConnected(deviceID: String)               // Active AWDL session
}
```

Note: Connection references (NWConnection, decoder, encoder) are NOT part of the state enum — they are managed by TransportManager as resources associated with the current state. The FSM deals in logical state only.

```swift
    case secureInputChanged(active: Bool)

    case heartbeatAck
}
```

`AgentTransportSideEffect` enum:

```swift
enum AgentTransportSideEffect {
    case startUSBIdentityTimer
    case cancelUSBIdentityTimer
    case startAWDLIdentityTimer(slotIndex: Int)
    case cancelAWDLIdentityTimer(slotIndex: Int)
    case promoteToActive(transport: ConnectionKind)

```

Pure transition function:
```swift
func agentTransportTransition(
    from state: AgentTransportState,
    on event: AgentTransportEvent

```

This function MUST be a free function (not a method) so it is trivially testable without any TransportManager instance. It should handle every (state, event) pair. For illegal/no-op transitions, return the same state with an empty side-effect list. Map the existing 19 cases from `activateConnection()` into this function — every case must be accounted for.

**Step 3 — iOS FSM (TransportStateMachine.swift):**

Create `KeydApp/KeydApp/Transport/TransportStateMachine.swift` with:

`iOSTransportState` enum — absorb boolean flags:
```swift
enum iOSTransportState: Equatable, CustomStringConvertible {
    case disconnected(awdlEnabled: Bool)
    case connecting(transport: ConnectionKind, awdlEnabled: Bool)
    case usbConnected
    case awdlConnected(awaitingHeartbeatAck: Bool)
    case backgroundSuspended(previousTransport: ConnectionKind?)
}
```

The `backgroundSuspended` state models the app lifecycle transition from TRANSPORT-STATE-ANALYSIS.md — when the app enters background, `UIApplication.beginBackgroundTask` is requested, and the FSM enters this state. On foreground, it transitions to `connecting` for fast reconnect without full backoff.

`iOSTransportEvent` enum:
```swift
enum iOSTransportEvent {
    case usbReady
    case usbDisconnected
    case awdlReady
    case awdlDisconnected
    case heartbeatAck
    case heartbeatTimeout
    case pairingCompleted
    case pairingFailed
    case appBackgrounded
    case appForegrounded
    case backgroundTaskExpiring
    case secureInputChanged(active: Bool)
    case retryRequested
}
```

`iOSTransportSideEffect` enum covering: startHeartbeat, stopHeartbeat, updateLiveActivity, resolveConnectionContinuation, beginBackgroundTask, endBackgroundTask, closeConnections, startReconnect, sendSessionResume, logEvent.

Pure transition function:
```swift
func iOSTransportTransition(
    from state: iOSTransportState,
    on event: iOSTransportEvent
) -> (iOSTransportState, [iOSTransportSideEffect])
```

Same rules: free function, handles every pair, no-op for illegal transitions.

**Design decisions (per TRANSPORT-STATE-ANALYSIS.md):**
- Single-paired model (simpler): keep one pairing slot, but send `pairingInvalidated` to previously paired device when a new device pairs. Multi-paired is deferred.
- `backgroundSuspended` state uses `beginBackgroundTask` for ~30s window, then graceful teardown. Fast reconnect on foreground skips backoff.
- Connection references (NWConnection etc.) stay in TransportManager, NOT in the state enum. The FSM is pure logic.

**Step 1 — macOS TransportManager refactor:**

Refactor `macOS/KeydAgent/Transport/TransportManager.swift` to:

1. Replace `connectionState: AgentConnectionState` with `fsmState: AgentTransportState` and a `TransportEventLog` instance.

2. Create a `handleEvent(_ event: AgentTransportEvent)` method that:
   - Calls `agentTransportTransition(from: fsmState, on: event)`
   - Updates `fsmState` to the new state
   - Records the transition in the `TransportEventLog`
   - Iterates through returned `[AgentTransportSideEffect]` and executes each one

3. Replace the 19-case `activateConnection()` switch and all direct state mutations with calls to `handleEvent()`. The existing methods (`handleUSBConnectionReady`, `handleAWDLConnection`, etc.) become event translators — they convert NWConnection callbacks into `AgentTransportEvent` values and call `handleEvent()`.

4. Remove all state-as-optional patterns: `pendingUSBDecoder` existence check becomes checking for `.pendingUSBIdentity` state. `pendingAWDLSlots` dictionary becomes associated with `.pendingAWDLPool` state.

5. Connection resources (NWConnection, decoder, encoder) are stored in a separate `ConnectionResources` struct managed alongside the FSM state — but the FSM itself does not reference them. Side effects like `.promoteToActive` trigger resource reassignment.

6. Replace `connectionEventLog: [String]` with the structured `TransportEventLog`. Expose `eventLog.export()` for the debug UI (same as existing pattern but structured).

**Step 2 — iOS TransportManager refactor:**

Refactor `KeydApp/KeydApp/Transport/TransportManager.swift` to:

1. Replace `connectionState: State` with `fsmState: iOSTransportState` and a `TransportEventLog` instance.

2. The `@Published` property should derive from `fsmState` — expose a computed `displayState` for SwiftUI bindings that maps FSM states to the existing UI states (disconnected, connecting, usbConnected, awdlConnected). This preserves all UI behavior.

3. Create `handleEvent(_ event: iOSTransportEvent)` with the same pattern: call transition function, update state, log, execute side effects.

4. Move ALL `connectionState.didSet` side effects into the side-effect executor. The 8 branching conditions (updateLiveActivity, heartbeat management, continuation resolution, session resume) become explicit `SideEffect` cases.

5. Absorb boolean flags:
   - `awdlEnabledForCurrentSession` -> part of `.disconnected(awdlEnabled:)` and `.connecting(awdlEnabled:)` states

6. Absorb continuation optionals: `connectionReadyContinuation` and `pairingResponseContinuation` become side effects (`.resolveConnectionContinuation`, `.resolvePairingContinuation`) triggered by the appropriate transitions.    - On foreground, skip full backoff — go directly to `.connecting`
