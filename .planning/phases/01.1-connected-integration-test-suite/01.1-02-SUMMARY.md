# Phase 01.1 Plan 02: Mac Agent Test-Mode Flag Summary

**--test-mode flag wires four test-safe behaviors into KeydAgent: 2s timeouts, stdout wire log with microsecond timestamps, in-memory-only pairing (no Keychain writes), and deterministic conn-N connection labels, plus a testReset handler that clears pairing state and sends testResetAck**

## Accomplishments

- Added `TestMode` struct with `identityTimeout`, `awdlSlotTimeout`, `verboseWireLog`, `connectionCounter` fields; passed through AppDelegate → PairingManager + TransportManager
- PairingManager now skips Keychain reads at init and Keychain writes in `completePairing` when `testMode != nil`; `resetInMemory()` clears state without touching Keychain
- TransportManager wires all four test behaviors: 2s USB/AWDL timeouts, `wireLog()` printing `[TEST-MODE] [MSG|HB] {ts} SEND|RECV: {msg}` to stdout, `nextConnectionLabel()` generating `conn-N` IDs, and `.testReset` case calling `pairingManager.resetInMemory()` then sending `.testResetAck`

## Decisions Made

- `TestMode` placed in `KeydAgentApp.swift` rather than a new file — keeps file count low per plan instruction
- `pairingManager` changed from `let` to `var` in AppDelegate so it can be reconstructed with `testMode` after flag detection (after SMAppService check, before status bar init)
- `testMode` is `var` on `TransportManager` (not `let`) to allow `connectionCounter` mutation via `nextConnectionLabel()`
- `testReset` is allowed through the not-paired guard in `handleIncomingMessage` so the test harness can issue a reset before any pairing has been established
- USB identity timeout stays 2.0s in both modes (it was already fast in production); AWDL slot timeout reduced to 2.0s in test mode (was 3.0s)
