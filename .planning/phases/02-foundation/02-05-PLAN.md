    **HEVCEncoder.h / HEVCEncoder.m (ObjC, macOS):**

    `@interface HEVCEncoder : NSObject`
    - `@property (nonatomic, assign) BOOL isActive`
    - `@property (nonatomic, copy) void(^onEncodedFrame)(const void *data, size_t len, MediaFrameHeader header)`
    - `- (void)startWithWidth:(int)width height:(int)height fps:(int)fps bitrate:(int)bitrate`
    - `- (void)encodePixelBuffer:(CVPixelBufferRef)pixelBuffer timestamp:(CMTime)timestamp`
    - `- (void)stop`
    - `- (void)switchToEcoMode` — changes to 1080p/720p at 30Hz (RD-COMP-07)
    - `- (void)switchToFullQuality` — restores original resolution and fps

    Implementation:
    - Create `VTCompressionSession` with `kVTVideoCodecType_HEVC`.
    - Encoder spec: `kVTVideoEncoderSpecification_EnableLowLatencyRateControl = YES`.
    - Session properties:
      - `kVTCompressionPropertyKey_RealTime = true`
      - `kVTCompressionPropertyKey_AllowFrameReordering = false` (no B-frames, low latency)
      - `kVTCompressionPropertyKey_AverageBitRate = bitrate` (50 Mbps for 4K, 15 Mbps for 1080p, 8 Mbps for 720p)
      - DO NOT set `kVTCompressionPropertyKey_DataRateLimits` or `ConstantBitRate` — these conflict with low-latency mode per research anti-pattern.
      - `kVTCompressionPropertyKey_ProfileLevel = kVTProfileLevel_HEVC_Main_AutoLevel`
    - Output callback: receives `CMSampleBufferRef` with H.265 NAL units. Extract data, create `MediaFrameHeader` with `flags |= 0x01` (HEVC flag), call `onEncodedFrame`.
    - `VTCompressionSessionEncodeFrame` for each pixel buffer.
    - Eco mode: tear down session, recreate with reduced dimensions and 30fps. The `SCStreamConfiguration` update (reduced resolution) happens at the ScreenCapture level — HEVCEncoder just adapts to whatever pixel buffers it receives.

    **HEVCDecoder.swift (iPadOS):**

    `class HEVCDecoder`:
    - `VTDecompressionSession` with `kVTVideoCodecType_HEVC`.
    - `func decode(data: Data, header: MediaFrameHeader) -> CVPixelBuffer?`
      1. Create `CMBlockBuffer` from data.
      2. Create `CMSampleBuffer` with format description.
      3. `VTDecompressionSessionDecodeFrame` — synchronous decode (low latency).
      4. Return decoded `CVPixelBuffer` (BGRA format).
    - Format description created from SPS/PPS extracted from first keyframe.
    - `var onDecodedFrame: ((CVPixelBuffer, UInt64) -> Void)?` — callback with pixel buffer and timestamp.
    - Handle session invalidation gracefully (recreate on error).

    **LZ4Decompressor.swift:**

    `class LZ4Decompressor`:
    - Pre-allocated buffers: `decompressBuffer` (size = display_width * display_height * 4 for BGRA), `keyframeReference` (same size, stores last keyframe for delta apply).
    - `func decompress(data: Data, header: MediaFrameHeader, frameBytes: Int) -> UnsafeRawPointer?`
      1. If `header.isKeyframe` (flags bit1):
         - `LZ4_decompress_safe` from data into decompressBuffer.
         - Copy decompressBuffer into keyframeReference (update reference for future deltas).
         - Return pointer to decompressBuffer.
      2. If `header.isDelta` (flags bit6):
         - `LZ4_decompress_safe` from data into a temp delta buffer.
         - Call `apply_delta(tempDeltaBuffer, keyframeReference, decompressBuffer, frameBytes)` via bridging header.
         - Copy decompressBuffer into keyframeReference (update reference for next delta).
         - Return pointer to decompressBuffer.
    - `init(frameBytes: Int)`:
      - Allocate decompressBuffer, keyframeReference, tempDeltaBuffer.
      - All pre-allocated — no per-frame malloc (matches Mac-side pattern from Plan 02).
    - `deinit`: deallocate all buffers.

    NOTE: `apply_delta` from delta.h is available via the bridging header. `LZ4_decompress_safe` from lz4.h is also available. Both are C functions callable from Swift.

    Ensure the decompress + delta apply total time target is <3ms per frame on iPad (RD-REND-04). The implementation should be straightforward given pre-allocated buffers and the M4 chip's memory bandwidth.
