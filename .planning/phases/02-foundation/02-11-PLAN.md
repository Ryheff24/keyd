Fix the blocker QR pairing failure: iPad cannot connect to Mac because the QR payload has no IP address and the Mac has no pairing listener.

Purpose: This is a blocker (UAT test 6). Without pairing, tests 7-14 are all blocked. The root cause is two-fold: (1) the Mac QR payload JSON contains port but no IP, so the iPad connects to "::" (IPv6 unspecified address) which is unroutable; (2) the Mac has no TCP listener accepting the incoming pairing connection on the advertised port.

Output: Working QR pairing flow -- Mac shows QR with its IP, iPad scans and connects, TLS cert-pinned connection succeeds, ECDH key exchange completes, shared secret stored in Keychain on both sides.

Fix the Mac side of QR pairing. Two changes needed:

**A. Add host IP to QR payload (PairingManager.m generateQRPayload):**

After the existing payload dictionary construction (around line 438), add a "host" field containing the Mac's routable IP address. Enumerate network interfaces using `getifaddrs()` to find a usable IPv4 address. Preference order:
1. USB NCM interface (bridge/en* interfaces with 169.254.x.x or NCM-specific addresses) -- check for interfaces named "bridge*" or with type matching USB NCM
2. en0 (primary Wi-Fi/Ethernet)
3. Any non-loopback IPv4 interface

Implementation: Create a helper method `- (nullable NSString *)bestRoutableIPv4Address` that:
```objc
#include <ifaddrs.h>
#include <arpa/inet.h>
```
- Calls `getifaddrs()` to enumerate interfaces
- Filters for AF_INET (IPv4), skips loopback (lo0)
- Collects all IPs, preferring en0
- Returns the best candidate as an NSString
- Frees the ifaddrs list

Add the host to the JSON payload dictionary:
```objc
NSString *hostIP = [self bestRoutableIPv4Address];
if (hostIP) {
    payload[@"host"] = hostIP;
}
```

The payload dictionary must be mutable -- change from `NSDictionary *payload = @{...}` to `NSMutableDictionary *payload = [@{...} mutableCopy]`.

Remove or update the "NOTE: QR payload has port but NO IP address" log line since it will now have an IP.

**B. Add TLS pairing listener (PairingManager.m and .h):**

Add to PairingManager.h:
```objc
/** Start a TLS listener for incoming pairing connections on KEYDRD_INPUT_PORT.
 *  Call before showing the QR code. Calls handlePairingConnection: when iPad connects. */
- (void)startPairingListener;

/** Stop the pairing listener. */
- (void)stopPairingListener;

/** Callback fired when pairing completes (ECDH done, secret stored). */
@property (nonatomic, copy, nullable) void (^onPairingComplete)(void);
```

Add to PairingManager.m:
- Private property: `@property (nonatomic, nullable) nw_listener_t pairingListener;`
- `startPairingListener` creates a TLS 1.3 listener on KEYDRD_INPUT_PORT using the existing `_tlsIdentity`:
  - Create TLS parameters with `nw_protocol_options_t` from `sec_protocol_options_set_local_identity`
  - Create TCP parameters with TLS
  - Set local endpoint to port KEYDRD_INPUT_PORT
  - Set listener state handler (log ready/failed/cancelled)
  - Set new connection handler that calls `[self handlePairingConnection:conn]`
  - Start listener
- `stopPairingListener` cancels the listener

- Update `handlePairingConnection:` to call `self.onPairingComplete()` after successful ECDH exchange (after sending the Mac public key back). Dispatch to main queue.
- Add `stopPairingListener` call in `handlePairingConnection:` after successful pairing (only need one connection).

Then wire in SessionManager.m:
- In `showPairingQR`, after generating the QR payload and before showing the QR window, call `[_pairing startPairingListener]`.
- Wire `_pairing.onPairingComplete` to transition from AWAITING_PAIRING to CONNECTING:
  ```objc
  __weak SessionManager *weakSelf = self;
  _pairing.onPairingComplete = ^{
      SessionManager *strongSelf = weakSelf;
      if (!strongSelf) return;
      os_log(sLog, "Pairing complete -- closing QR window and starting transport");
      [strongSelf.qrWindow close];
      strongSelf.qrWindow = nil;
      [strongSelf transitionTo:SESSION_CONNECTING];

  ```
  This wiring should go in `showPairingQR` before the listener start, or in the `onPermissionsGranted` method.
