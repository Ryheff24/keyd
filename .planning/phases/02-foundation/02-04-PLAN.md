    **Pre-TLS Pairing Bootstrap Design (CRITICAL):**

    The chicken-and-egg problem: iPad cannot open a TLS connection without knowing who to trust, and cannot complete ECDH without a connection to send its public key. The solution uses the QR code as the trust anchor for the FIRST TLS connection:

    1. **Mac generates a self-signed TLS certificate** (P-256 key pair via `SecKeyCreateRandomKey`) and stores it in Keychain. This cert is used as the Mac's TLS server identity for ALL connections.
    2. **Mac computes SHA-256 fingerprint** of its self-signed certificate's DER encoding.
    3. **QR payload includes the cert fingerprint** alongside the existing fields. This is the trust anchor — physical proximity (scanning QR) proves the fingerprint is authentic.
    4. **iPad scans QR, extracts cert fingerprint**, then opens a TLS connection to the Mac. In the TLS verify block, iPad compares the server certificate's SHA-256 fingerprint against the QR-provided fingerprint. If match: trust. If mismatch: reject (MITM detected).
    5. **ECDH completes OVER the cert-pinned TLS channel**: iPad sends its Curve25519 public key, Mac sends its Curve25519 public key, both derive shared secret. This is fully encrypted — no cleartext key exchange.
    6. **After ECDH, derive and store long-term pinning data**: Both sides store each other's identity (cert fingerprint for Mac, derived identity for iPad) in Keychain for subsequent connections without re-pairing.

    This means: NO cleartext connection ever exists. The QR code bridges the trust gap.

    **macOS PairingManager.h / PairingManager.m (ObjC):**

    Pattern-copy from keyd v1.0 `macOS/KeydAgent/Pairing/PairingManager.swift` but rewrite in ObjC.

    `@interface PairingManager : NSObject`
    - `@property (nonatomic, readonly) BOOL isPaired`
    - `@property (nonatomic, readonly) NSData *sharedSecret`
    - `@property (nonatomic, readonly) SecIdentityRef tlsIdentity` — the Mac's self-signed TLS identity (persisted in Keychain).
    - `- (void)ensureTLSIdentity` — on first run, generates P-256 key pair via `SecKeyCreateRandomKey`, creates self-signed X.509 certificate, packages as `SecIdentity`, stores in Keychain under `KEYDRD_KEYCHAIN_SERVICE` account `"tls-identity"`. On subsequent runs, loads from Keychain. Called before QR generation.
    - `- (NSData *)tlsCertFingerprint` — returns SHA-256 of the self-signed certificate's DER encoding (`SecCertificateCopyData` then `CC_SHA256`).
    - `- (NSString *)generateQRPayload` — generates QR code string containing:
      1. Mac's self-signed cert SHA-256 fingerprint (hex string) — **this is the trust anchor**
      2. Mac's Curve25519 public key (base64)
      3. Display geometry (width, height, scale factor)
      4. Protocol version (1)
      5. Service name (_keydrd._tcp)
      6. TCP pairing port (KEYDRD_INPUT_PORT)
      Format: JSON for QR payload only (this is the ONE place JSON is used; all subsequent communication is binary).
    - `- (void)handlePairingConnection:(nw_connection_t)conn` — receives iPad's Curve25519 public key over the cert-pinned TLS connection, performs ECDH, derives shared secret, generates iPad's TLS identity from shared secret, stores both in Keychain.
    - `- (BOOL)completePairing:(NSData *)iPadPublicKey` — performs ECDH key agreement, derives shared secret via HKDF, stores in Keychain under `KEYDRD_KEYCHAIN_SERVICE`.
    - `- (void)resetPairing` — deletes Keychain entries (shared secret + peer cert).
    - `- (NSData *)loadStoredPeerCertificate` — loads stored peer cert for cert pinning on subsequent connections.

    Use Security.framework for key generation:
    - `SecKeyCreateRandomKey` with `kSecAttrKeyTypeECSECPrimeRandom` for TLS identity (P-256).
    - `CryptoKit` bridge or raw `SecKeyCopyKeyExchangeResult` with `kSecKeyAlgorithmECDHKeyExchangeStandard` for ECDH.
    - Store derived shared secret in Keychain with service `KEYDRD_KEYCHAIN_SERVICE`, account `"pairing"`.

    The Mac's NWListener for the pairing TCP port uses the self-signed `SecIdentity` as its TLS server identity via `sec_protocol_options_set_local_identity`.

    **iPadOS QRPairing.swift:**

    Pattern-copy from keyd v1.0 pairing but with new service name and cert-pinned bootstrap.

    `class QRPairing: NSObject, AVCaptureMetadataOutputObjectsDelegate`:
    - `AVCaptureSession` with back camera, metadata output for `.qr`.
    - `func startScanning()` — starts camera session, shows viewfinder.
    - `metadataOutput(_:didOutput:from:)` — parses QR JSON payload, extracts Mac's cert fingerprint, public key, and display geometry.
    - `func completePairing(qrPayload: QRPayload)`:
      1. Extract `expectedCertFingerprint` from QR payload (hex string -> Data).
      2. Open TLS connection to Mac at `KEYDRD_INPUT_PORT` with **fingerprint-pinned verify block**:
         ```swift
         sec_protocol_options_set_verify_block(secOptions, { metadata, trust, complete in
             let serverCert = sec_trust_copy_certificate_chain(trust)
             let certData = SecCertificateCopyData(serverCert[0]) as Data
             let fingerprint = SHA256.hash(data: certData)
             let trusted = fingerprint == expectedCertFingerprint
             complete(trusted)  // Reject if fingerprint doesn't match QR
         }, .main)
         ```
      3. Over this cert-pinned TLS channel, generate iPad's Curve25519 key pair: `CryptoKit.Curve25519.KeyAgreement.PrivateKey()`.
      4. Send iPad's public key to Mac (binary, 32 bytes).
      5. Receive Mac's Curve25519 public key from Mac (binary, 32 bytes).
      6. Perform ECDH: `iPadPrivateKey.sharedSecretFromKeyAgreement(with: macPublicKey)`.
      7. Derive symmetric key via HKDF.
      8. Store shared secret + Mac cert fingerprint in Keychain under `KEYDRD_KEYCHAIN_SERVICE`.
    - `var isPaired: Bool` — checks Keychain for stored secret.
    - `func resetPairing()` — deletes Keychain entry.
    - Store display geometry from QR payload for use in rendering setup.
